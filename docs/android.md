# Android testing and release

GlowBook includes a Capacitor Android project with application ID `za.co.glowbook.app`. The repository CI can build a free, installable debug APK, so Android Studio is not required merely to preview the application on a physical phone.

## Download the CI test APK

1. Open the pull request on GitHub and select **Checks** or **Actions**.
2. Open the latest successful **CI** workflow run.
3. In **Artifacts**, download `glowbook-android-debug`.
4. Extract the ZIP and transfer `app-debug.apk` to the Android phone.
5. Open the APK on the phone and allow installation from that source when Android asks.

The artifact expires after 14 days and can be regenerated by another CI run. It is signed with an automatically generated debug key and is intended only for development testing. Do not distribute it as a production release.

The current production mobile build has no public API URL. The interface can be inspected in the APK, but registration, sign-in, discovery data, and bookings require the ASP.NET API to be hosted at an HTTPS address reachable by the phone. No API host or cloud resource is created automatically.

## Build and run locally

Install Android Studio with its Android SDK and a compatible JDK, then run:

```powershell
Set-Location apps/mobile
npm.cmd ci
npm.cmd run android:sync
npx.cmd cap open android
```

Choose a connected phone with USB debugging enabled, or an emulator, and run the app from Android Studio. After web-code changes, run `npm.cmd run android:sync` before rebuilding the native app.

To refresh the launcher icons after changing `assets/icon-only.png`, run `npm.cmd run assets:android` and review the generated Android resources.

## Play Store release prerequisites

A production Play Store release is deliberately not automated yet. It requires owner decisions and credentials that must not be committed:

- an owner-controlled Google Play Console developer account and its registration fee;
- Google identity and developer-account verification;
- a stable HTTPS production API and PostgreSQL database;
- an approved privacy policy, Play Data safety declaration, store listing, screenshots, support contact, and content rating;
- a protected upload signing key, with passwords supplied through secure CI secrets;
- a release Android App Bundle (`.aab`), versioning, and Play App Signing;
- completion of the testing requirements that apply to the Play Console account.

Before release, the production API URL must be configured without hard-coding secrets, native secure token storage must be reviewed, and the full booking flow must pass tests against a production-like environment. CI must never publish to Google Play or apply infrastructure changes without explicit release approval.
