# Notifications and enriched Glow Spaces

Authenticated users have an in-app notification centre with unread state and record-specific links for booking, application, account-review and appointment-reminder events. Booking reminders are generated approximately 24 hours before confirmed appointments. Notification preferences control booking, application, account and reminder push categories. Email remains the fallback when a registered push device or configured provider is unavailable.

Android permission is requested only after the user chooses **Enable Android push**. Device tokens are encrypted with ASP.NET Core Data Protection, identified by a one-way hash for rotation, never returned by the API, and can be revoked from the same device. Production must persist and protect the Data Protection key ring. Firebase Cloud Messaging is optional and owner-controlled: set `Firebase__ProjectId`, `Firebase__ClientEmail` and `Firebase__PrivateKey` through protected configuration and add the owner-provided `google-services.json` during the signed Android release workflow. With no Firebase configuration, notification delivery falls back without blocking in-app use. Do not commit either credential.

Glow Spaces supports up to five HTTPS gallery links in addition to the legacy cover image, private saved opportunities, one report per user/listing, optional session-only distance, and derived urgency/expiry states. “Starting or closing soon” means the start or end date is within seven days; expired means the end date has passed. “Approved business” reflects administrator approval only and is not a guarantee; seeded businesses retain an explicit demo label. Exact search coordinates are neither returned nor persisted.
